# Goal Prompt

# GOAL: Show Codex plan labels in provider and quota views

## Context

GitHub issue [decolua/9router#2569](https://github.com/decolua/9router/issues/2569) reports that Codex accounts became difficult to distinguish after removal of the 5-hour quota bar as a visual cue. Users managing multiple Codex accounts need to see each account's ChatGPT/Codex plan, for example `Pro` or `Free`, without opening details or inferring the plan from quota windows.

This workspace is an updated fork at `CarmeloCampos/9router`, currently based on commit `9845a17` (`v0.5.30`). The upstream repository's default branch is `master`; its relevant UI files currently have the same omission. No upstream pull request was found for issue #2569 as of 2026-07-12.

The requested data already exists in the current application. This is primarily a small presentation change, not a plan-detection feature.

## Problem

The application obtains Codex plan data through two existing paths but does not render it in the two requested views:

1. Codex OAuth and token-import flows persist the plan as `connection.providerSpecificData.chatgptPlanType`. The Codex provider detail page receives this connection object, but `ConnectionRow` renders status, authentication type, proxy state, cooldown, priority, and test state without rendering the plan.
2. The Codex usage handler reads the upstream usage response's `plan_type` and returns it as `plan`. `ProviderLimits` stores that value in `quotaData[connectionId].plan`, but the quota card header never renders it.

Consequently, Free, Plus, Pro, Team, Enterprise, or other Codex plans can look identical when their visible quota windows are the same or absent.

## Objective

Expose the already-available Codex plan label in both requested dashboard locations:

- Each Codex account row on the Codex provider detail page.
- Each Codex account card on the quota page.

The label must be textual, compact, readable in light and dark themes, visually consistent with existing badges, safe when plan data is missing, and restricted to Codex accounts. Existing provider, quota, authentication, refresh, sorting, pagination, proxy, and account-management behavior must remain unchanged.

## Scope

- Update `src/app/(dashboard)/dashboard/providers/[id]/ConnectionRow.js` to render a Codex plan badge using `connection.providerSpecificData.chatgptPlanType`.
- Update `src/app/(dashboard)/dashboard/usage/components/ProviderLimits/index.js` to render a Codex plan badge using `quotaData[connectionId].plan` after quota data loads.
- Reuse `src/shared/components/Badge.js`; do not create another badge component or plan-label abstraction for two conditional render sites.
- Present ordinary lowercase API values in a human-readable form, for example `pro` as `Pro` and `free` as `Free`. Prefer presentation-only capitalization, such as the existing utility class `capitalize`, so the underlying API value is not rewritten.
- Render any future non-empty Codex plan string rather than maintaining a hardcoded allowlist. Known examples are not the full contract.
- Suppress blank values and the usage handler's fallback value `unknown`; absence of reliable data should produce no plan badge, not an `Unknown` badge.
- Keep the badge visible alongside existing account metadata without displacing controls or breaking narrow/mobile layouts.
- Update local `PropTypes` only where needed to describe newly accessed connection fields.
- Verify both changed views and regressions in nearby account UI.
